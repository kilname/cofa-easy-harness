# Cofa Easy Harness v2 — Shell edition (비공식 · Codex용)

**비공식 준비 자료이며 실제 과제의 정답·코드를 포함하지 않습니다.**

과제의 정답을 제공하지 않고 Codex가 **요구사항 이해 → 질문 → 최소 구현 → 실제 테스트 → 비판적 검증 → 제출 준비**를 반복하도록 안내하는 한국어 범용 하네스입니다.

- 외부 AI 모델 호출, 원격 MCP, 자동 제출, 개인 API 키 없음.
- 원본 과제 README·정책을 덮어쓰지 않음.
- 시험에서는 공개 저장소에서 Clone하는 방식만 고려하며, 실제 응시 환경의 규칙이 우선함.

## 작업 모드 선택
- **학습 모드:** **내가 먼저 분석하고 AI는 근거로 검토**한다. 답을 선공개하지 않고, 질문의 범위에 맞춰 정확히 채점하며, 막히면 단계별로 힌트를 준다. 요청 전에는 코딩하지 않는다.
- **실전 모드(기본):** 초기 핵심 분석 후 **확정된 필수 기능을 구현·즉시 테스트**한다. **사용자 핵심 검토 3회(요구사항·설계 선택·실제 검증 결과)**를 개발 과정 안에 포함하되, 사소한 사항까지 매번 승인받지는 않는다. 사용한 기술은 실제 코드 근거로 짧게 설명한다.
- 모드 전환은 Codex에 한 문장만 입력하면 된다. **선택 구성: 같은 프로젝트 폴더에서 B(학습·검토)를 먼저 시작해 문제를 이해하고, B가 최초 `COFA_TO_A.md` 개발 지시서를 작성하면 사용자가 A(개발)에 전달한다. A 개발 중에도 B와 학습·검토를 계속하고 이후 수정 요청도 같은 파일로 전달한다.** 이 방식은 Codex 세션 간 자동 연결이나 하위 에이전트를 사용하지 않는다. 상세 사용법은 [START_HERE.md](START_HERE.md)와 [COFA_DUAL_SESSION.md](COFA_DUAL_SESSION.md)에 있다.

**처음 보는 사람:** [`START_HERE.md`](START_HERE.md) **파일명 하나만 기억하세요.** 설치기가 과제 폴더에 이 파일을 추가하므로, Codex에 'START_HERE.md 읽고 튜터 B부터 시작해줘'라고 말하면 내부 상세 지침도 스스로 찾아 읽도록 안내합니다. 기존 파일이 있으면 덮어쓰지 않습니다.

**사용법 (과제 README.md가 있는 디렉터리의 POSIX sh 지원 터미널):**

```bash
git clone --depth 1 https://github.com/kilname/cofa-easy-harness.git .cofa-harness
sh .cofa-harness/install.sh .
```

먼저 클론과 설치가 허용되는지 확인하세요. 기존 `.cofa-harness`가 있을 때 덮어쓰지 마세요.

**핵심 프롬프트:**

> 실전 모드로 시작해줘. README와 제출 규칙을 빠르게 읽고, 내가 확인할 핵심 검토 지점 3개(요구사항·중요 설계·최종 검증)를 짧게 제시해줘. 확정된 기능은 바로 구현하고 실제 테스트해줘. 기술은 구현한 코드 근거로 쉽게 설명하고, 사소한 결정은 묻지 마. 미확정 업무 정책은 임의 확정하지 말고, 제출 전 미검증 사항까지 알려줘.

하네스 파일 구조는 `sh doctor.sh`, 설치기 테스트는 `sh tests/test_harness.sh`로 점검합니다. 이는 시험 환경에서의 안전성·정확성 보증이 아닙니다.
